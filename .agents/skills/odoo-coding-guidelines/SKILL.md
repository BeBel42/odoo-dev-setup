# Odoo Coding Guidelines

Full documentation: `documentation/content/contributing/development/coding_guidelines.rst`

These are the **most commonly violated rules**: enforce them strictly.

---

## Linting (Ruff)

- **Main config**: `community/ruff.toml` (targets py312, `preview = true`)
- **Workspace symlink**: `ruff.toml` at the workspace root is a symlink to `community/ruff.toml`
- **Separate configs**: `upgrade/` and `upgrade-util/` have their own `ruff.toml`

The `community/ruff.toml` header notes it is **generated by runbot's nightly checks**: do not hand-edit it.

If you need project-specific overrides, create a separate config or use inline comments.

## Python Guidelines

### Never Commit/Rollback Cursors You Didn't Create

```python
# WRONG - never do this
cr.commit()
cr.rollback()

# RIGHT - use savepoints for controlled rollback
with self.env.cr.savepoint():
    # operations that might fail
```

### Catch Specific Exceptions

```python
# WRONG
try:
    do_something()
except Exception:
    pass

# RIGHT - narrow try block, specific exception
try:
    record.action_confirm()
except UserError as e:
    logger.warning("Confirmation failed: %s", e)
```

**Note**: Use `self.env.cr.savepoint()` sparingly; more than 64 savepoints per transaction degrades PostgreSQL.

### Translation Strings

```python
# WRONG - dynamic string
_(f"Hello {name}")
_("Hello " + name)
_("Hello %s" % name)

# RIGHT - static literal, _ does the formatting
self.env._("Hello %(name)s", name=name)
```

- Always use static literal strings.
- Prefer `%(name)s` over positional `%s`.
- Never pass field values or computed strings to `_()`.

### Model Attribute Order

1. Private attributes (`_name`, `_description`, `_inherit`)
2. Default methods
3. Field declarations
4. SQL constraints
5. Compute/inverse/search methods
6. Selection methods
7. `@api.constrains` / `@api.onchange`
8. CRUD overrides (`create`, `write`, `unlink`)
9. `action_*` methods
10. Other business methods

### Context Is Frozen

```python
# WRONG
self.env.context['my_key'] = value

# RIGHT - use with_context
records = self.with_context(module_name_my_key=value)
```

Namespace custom context keys with the module name.

## XML Guidelines

### ID Naming Conventions

| Type    | Pattern                     | Example                       |
|---------|-----------------------------|-------------------------------|
| Views   | `<model>_view_<type>`       | `sale_order_view_form`        |
| Actions | `<model>_action[_<detail>]` | `sale_order_action_quotation` |
| Menus   | `<model>_menu[_<x>]`        | `sale_order_menu_main`        |
| Groups  | `<module>_group_<name>`     | `sale_group_manager`          |
| Rules   | `<model>_rule_<group>`      | `sale_order_rule_manager`     |

The record `name` attribute should mirror the `id` with dots.

### View Inheritance

- **Inheriting views** reuse the **same** `id` as the original.
- **New primary views** (`mode="primary"`) get a new unique id.

### Noupdate Flag

```xml
<!-- Only for non-updatable data -->
<data noupdate="1">
    <record id="..." model="...">
        ...
    </record>
</data>
```

## JS / SCSS Guidelines

### CSS Class Naming

- Prefix with `o_<module_name>` (webclient uses bare `o_`)
- **No `id` selectors**
- **No hyper-nesting**

```scss
// WRONG
#my-element { ... }
.container .row .col .card .header .title { ... }

// RIGHT
.o_sale_order_form { ... }
.o_sale_order_header { ... }
```

### External Assets

- **Never** add minified libraries directly
- **Never** hotlink external assets
- Copy external libraries into `static/` (e.g., `static/lib/`)
